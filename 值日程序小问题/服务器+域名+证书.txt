

                                  Nginx 配置片段
----------------------1。这是写证书的主要操作---------------------------------------------------------------------------------------------------------------------------------------
# 1. IP 访问：直接走 HTTP，不跳转，不触发证书校验
server {
    listen 80;
    server_name 121.41.20.177; # 明确指定只匹配 IP 地址
    location / {
        proxy_pass http://127.0.0.1:8000; # 转发给后端程序
        # ... 其他 proxy_set_header 配置
    }
}

# 2. 域名访问（HTTP）：强制跳转到 HTTPS
server {
    listen 80;
    server_name duty.yoga www.duty.yoga; # 明确指定只匹配域名
    return 301 https://$host$request_uri; # 301 永久重定向到 HTTPS
}

# 3. 域名访问（HTTPS）：正常处理加密请求
server {
    listen 443 ssl;
    server_name duty.yoga www.duty.yoga;
    
    ssl_certificate /etc/nginx/duty.yoga.pem;
    ssl_certificate_key /etc/nginx/duty.yoga.key;
    # ... 其他 SSL 配置和 proxy_pass 转发
}        location / {
            proxy_pass http://127.0.0.1:8000;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }
}







🏗️ 核心概念的关系梳理
--------------服务器（本地部署 vs 云服务器）---------------------
关系：这是你存放代码、数据库和运行程序的“场地”。
比喻：本地部署就像是在你自己家里做饭，只有你自己能吃；云服务器部署（比如阿里云）就像是你花钱在商业街上租了一个店铺，做好了准备对外营业。
 -------------      ------域名-----------------------------------
关系：它是服务器的“门牌号”或“招牌”。
比喻：如果没有域名，顾客想找到你的店铺，必须输入一串难记的坐标（也就是服务器的 IP 地址，如 121.41.20.177）。有了域名（如 duty.yoga），顾客就能通过好记的名字直接找到你。
--------------------------------SSL 证书（HTTPS）-------------------------
关系：它是给网站数据传输加的“安全锁”和“防伪标签”。
比喻：就像给店铺装了防弹玻璃和官方认证的安全标识。顾客（浏览器/小程序）看到有这个标识（网址开头是 https:// 且有小锁图标），才敢放心地在里面提交敏感信息（比如登录密码、支付信息）。如果没有证书，浏览器就会拦截并提示“不安全”。
-----------------------------------------------------上线------------------------------------
关系：这是最后“正式开门营业”的动作。
比喻：你在家里把菜做好（本地开发测试），搬到租好的店铺里（服务器部署），挂好招牌（绑定域名），装好安全锁（配置 SSL 证书），最后打开大门迎接顾客（正式上线）。
